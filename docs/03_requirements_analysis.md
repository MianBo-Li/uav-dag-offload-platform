# 需求分析文档

## 1. 文档目的

本文档用于明确系统第一阶段要解决的真实业务问题、核心使用流程、功能需求、非功能需求和异常场景。后续系统设计、数据库设计、API 设计和测试用例都以本文档为依据。

## 2. 业务目标

系统需要支持一个完整的无人机 DAG 任务卸载调度闭环：

用户提交 DAG 任务，系统根据无人机、边缘节点和任务依赖关系生成调度计划，将子任务下发给模拟执行节点，执行节点回传结果，系统记录任务状态和评估指标。

## 3. 角色定义

### 任务用户

提交无人机任务，查看任务状态、执行结果和调度效果。

### 节点 Agent

代表无人机或边缘节点，负责注册、心跳上报、资源上报、接收任务、回传结果。

### 调度器

根据任务 DAG、节点资源和调度策略生成任务执行计划。

### 系统管理员

查看系统运行状态、节点状态、任务异常和日志。

## 4. 核心业务流程

### 主流程：任务提交到执行完成

1. 节点 Agent 注册无人机和边缘节点。
2. 节点 Agent 周期性上报电量、CPU、内存、网络状态和负载。
3. 任务用户提交 DAG 任务。
4. 系统校验 DAG 是否合法。
5. 系统读取当前节点资源状态。
6. 调度器生成任务卸载计划。
7. 系统将子任务分配给对应执行节点。
8. 执行节点模拟执行子任务。
9. 执行节点回传执行结果。
10. 系统更新子任务和总任务状态。
11. 用户查询任务结果和性能指标。

## 5. 功能需求

### FR-001 节点注册

系统应支持注册无人机节点和边缘节点。

节点信息至少包括：

- 节点类型
- 节点名称
- CPU 容量
- 内存容量
- 网络地址
- 初始状态

### FR-002 节点状态上报

系统应支持节点周期性上报状态。

无人机状态至少包括：

- 电量
- CPU 使用率
- 内存使用率
- 网络质量
- 位置

边缘节点状态至少包括：

- CPU 使用率
- 内存使用率
- 当前负载
- 可用任务队列长度

### FR-003 DAG 任务创建

系统应支持用户创建 DAG 任务。

任务信息至少包括：

- 任务名称
- 子任务列表
- 子任务依赖关系
- 子任务计算量
- 子任务输入数据大小
- 子任务输出数据大小
- 截止时间或优先级

### FR-004 DAG 合法性校验

系统应校验：

- 子任务 ID 不重复
- 依赖的子任务存在
- 不存在环形依赖
- 至少存在一个入口子任务
- 至少存在一个出口子任务

### FR-005 调度计划生成

系统应根据 DAG 结构和节点状态生成调度计划。

调度计划至少包括：

- 每个子任务的执行节点
- 每个子任务的预计开始时间
- 每个子任务的预计结束时间
- 预计能耗
- 预计传输耗时

### FR-006 任务执行与回传

系统应支持模拟执行节点执行子任务并回传结果。

执行结果至少包括：

- 执行状态
- 实际开始时间
- 实际结束时间
- 实际耗时
- 失败原因
- 输出摘要

### FR-007 任务状态查询

系统应支持查询：

- 总任务状态
- 子任务状态
- 调度计划
- 执行记录
- 失败原因
- 性能指标

### FR-008 失败重试

当子任务执行失败时，系统应根据重试策略进行重试，并记录每次重试。

### FR-009 节点离线检测

当节点超过心跳超时时间未上报时，系统应将节点标记为离线。

### FR-010 调度策略对比

系统至少应支持以下调度策略：

- 本地执行策略
- 随机卸载策略
- 贪心调度策略

## 6. 非功能需求

### NFR-001 可维护性

代码应按模块组织，调度策略应可插拔。

### NFR-002 可测试性

核心调度逻辑、DAG 校验、状态流转必须具备自动化测试。

### NFR-003 可观测性

系统应记录关键日志，并在后续阶段支持指标监控。

### NFR-004 可部署性

系统应支持通过 Docker Compose 启动开发环境。

### NFR-005 一致性

任务状态更新应避免重复回调导致状态错乱。

## 7. 核心状态

### 任务状态

- `PENDING`
- `SCHEDULED`
- `RUNNING`
- `SUCCESS`
- `FAILED`
- `CANCELED`

### 子任务状态

- `WAITING`
- `READY`
- `DISPATCHED`
- `RUNNING`
- `SUCCESS`
- `FAILED`
- `RETRYING`

### 节点状态

- `ONLINE`
- `BUSY`
- `OFFLINE`

## 8. 异常场景

### AS-001 DAG 不合法

当 DAG 存在环或依赖不存在时，系统应拒绝创建任务并返回错误原因。

### AS-002 无可用节点

当没有可用执行节点时，系统应将任务保持为等待调度状态。

### AS-003 节点执行失败

当子任务失败时，系统应记录失败原因，并根据重试策略决定是否重试。

### AS-004 节点离线

当节点离线时，系统应标记受影响的子任务，并在后续阶段支持重新调度。

### AS-005 重复结果回传

当执行节点重复回传同一子任务结果时，系统应保证状态幂等。

## 9. 第一阶段验收用例

1. 注册 1 架无人机和 1 个边缘节点。
2. 上报两个节点的资源状态。
3. 提交一个包含 5 个子任务的 DAG。
4. 系统校验 DAG 合法。
5. 使用贪心策略生成调度计划。
6. 模拟 Worker 执行全部子任务。
7. 查询任务最终状态为 `SUCCESS`。
8. 查询每个子任务的执行节点、耗时和结果。
